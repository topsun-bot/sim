# 巡检仿真证据合同（提案）

> 适用于本仓库 MCAP → MuJoCo / Isaac Sim 回放结果的复现、评审和后续现场验收准备。
>
> 本文只定义证据合同，不表示当前回放结果已经通过真机、连续运行、安全认证或生产验收。

## 1. 为什么需要合同

当前输出中的 `sim_success`、跟踪误差和对比视频可以证明一次回放发生了什么，但不能单独回答：

- 输入数据、场景、配置和随机种子是否冻结；
- 失败、人工接管和重试是否仍在任务分母中；
- 仿真没有建模的摩擦、碰撞、网络、传感器和人员变量是什么；
- 接口成功是否对应状态迁移、物理响应和最终任务完成；
- 结果能否由另一台机器按同一版本复现。

因此，每次正式评审应同时保存输入身份、运行身份、任务分母、原始结果和证据边界。

## 2. 最小运行清单

建议为每次执行分配不可复用的 `attempt_id`，并在
`output/<episode_id>/<attempt_id>/` 中增加 `evidence_manifest.json`。重试和更换随机种子都必须创建新目录，禁止覆盖先前失败、取消或已完成执行的日志、视频和指标。清单至少包含：

## 3. 固定任务分母

在运行前冻结：

- 计划 episode 数；
- 每个 episode 的起止状态和成功条件；
- 超时、取消、接管和失败条件；
- 允许重试次数；
- 需要执行的故障注入；
- 需要保留的原始文件。

至少同时报告三类指标，不能只展示重试后的最好结果：

- 逻辑任务完成率：`R_logical = 最终完成的逻辑 episode 数 / 预先冻结的逻辑 episode 总数`；
- 首次尝试成功率：`R_first = 首次尝试成功的逻辑 episode 数 / 预先冻结的逻辑 episode 总数`；
- 尝试级成功率：`R_attempt = 成功 attempt 数 / 实际执行的全部 attempt 数`。

失败、取消、接管和重试前 attempt 不能从尝试级分母删除；某逻辑 episode 经重试成功时，可以计入 `R_logical` 的最终完成数，但不能回写为首次尝试成功，也不能覆盖失败 attempt。样本量小的时候同时展示全部原始结果和三个整数分子/分母，不用多位小数制造精确感。

## 4. 请求、状态、物理和任务分层

以下命题必须分开记录：

1. 请求被接口接受；
2. 控制/仿真状态发生预期迁移；
3. 机器人模型产生预期物理响应；
4. 任务达到预先冻结的完成条件。

返回码 0 或 HTTP 2xx 只支持第 1 层，不能直接写成“已运动”“已停止”或“任务成功”。

## 5. 仿真没有证明什么

至少逐项声明：

- 接触摩擦、轮胎/足端形变与地面材料；
- 载荷、质心、惯量和末端工具；
- 传感器视场、噪声、遮挡、漂移和时间同步；
- 网络丢包、抖动、带宽和时钟偏差；
- 固件模式、控制权、lease 和竞争发布者；
- 人员误入、疲劳、惊吓和人工接管；
- 真实设备的温度、磨损、防护和认证边界。

仿真成功最多记为 `E2_SIMULATION`。它不能自动升级为 `E3_CONTROLLED_SITE`、连续试运行或生产验收。

## 6. 故障注入

建议至少覆盖：

| 故障 | 期望结果 | 必留证据 |
|---|---|---|
| 输入时间戳跳变 | 有界失败或拒绝运行 | 原始时间戳、错误、退出码 |
| 关节状态缺失 | 不用陈旧值静默继续 | 缺失区间、状态机、输出 |
| 配置/场景哈希不符 | fail closed | 期望/实际哈希 |
| 控制超时 | 进入约定保持/停止状态 | 命令、状态、物理轨迹 |
| 后端异常退出 | 结果标记失败 | 日志、最后状态、未完成任务 |
| 随机种子变化 | 可比较且不覆盖原结果 | seed、指标和原始产物 |

## 7. 跨学科复核

- **物理学**：质量、惯量、摩擦、接触、停止距离和传感器几何是否在模型中？没有建模的变量是否显式列出？
- **数学**：任务分母、失败、接管、缺失值和不确定性是否保留？是否在看完结果后改阈值？
- **逻辑学**：是否把请求成功、状态改变、物理响应和任务完成错误地互相推出？
- **生物/人因**：现场人员、观察员、紧急接管和培训是否被错误地折叠为软件指标？
- **心理学**：是否只选择最好一次回放，或用漂亮视频替代全量失败记录？

## 8. 与现场验收的衔接

进入任何真机运动前，应另行完成准确机器人/固件/载荷身份、现场授权、清场、观察员、人工接管、独立停止、命令所有权和日志时钟基准检查。本合同不会发送真机命令。
